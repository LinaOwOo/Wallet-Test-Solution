
# 💰 Flutter Wallet App

Данный репозиторий содержит решение тестового задания для Flutter-приложения кошелька. 
В рамках работы были не только реализованы ключевые фичи, но и проведена глубокая рефакторинг-работа: исправлены проблемы с управлением зависимостями, жизненным циклом BLoC, асинхронными операциями и сетевыми запросами.

### 🎯 Основной фокус работы

* Работа с адресами кошелька и буфером обмена.
* Синхронизация статуса транзакций (Retry, Idempotency, Cancellation).
* Выпуск карты и управление состоянием.
* Авторизация, Deep Links и навигация (`GoRouter`).
* Настройка Dependency Injection (`GetIt`).
* Покрытие кода Unit и Widget тестами.


## 🛠 Реализованные изменения

## 1. 📍 Работа с адресом кошелька
* **Форматирование:** Реализовано корректное отображение адреса (например, `0x1234...abcd`). Логика вынесена в чистую функцию (Pure Function), что позволяет легко её тестировать без привязки к UI.
* **Копирование в буфер:** 
  * Копирование полного адреса и отображение статуса (Success/Error).
  * Автоматический сброс состояния и корректная отмена таймеров при `dispose` BLoC.
* **Жизненный цикл:** `AddressTileBloc` получает зависимости через `GetIt`. При уничтожении виджета BLoC и связанные ресурсы корректно закрываются, что исключает утечки памяти и проблемы в widget-тестах.

## 2. 🔄 Синхронизация статуса транзакций
Реализован надежный сервис синхронизации с сервером с учетом всех edge-cases.
* **Идемпотентность:** Для каждого запроса формируется стабильный `Idempotency-Key` в формате `<network>:<txHash>` (например, `ethereum:0x1234abcd`). Это предотвращает дублирование операций на бэкенде.
* **Retry-механизм:** Повтор запроса (до 3 попыток) для временных ошибок:
  * `408 Request Timeout`
  * `429 Too Many Requests`
  * `503 Service Unavailable`
  * Сетевые ошибки `Dio`.
  * *Примечание:* Ошибки `401` и `500` не вызывают retry.
* **Отмена запросов (Cancellation):** При отмене операция немедленно завершается, новые HTTP-запросы не уходят, данные не сохраняются в БД.
* **Локальное сохранение:** Результат пишется в локальное хранилище **только** после успешного ответа сервера. Ошибки сохранения маппятся в `localPersistenceFailed` для сохранения консистентности.

## 3. 💳 Выпуск карты (Card Issuing)
Доработан `CardIssuePage` с полным разделением ответственности:
* Убрано создание зависимостей внутри UI.
* `ICardIssuer` и `CardIssueBloc` резолвятся через `GetIt`.
* Реализована защита от повторного вызова `cancelPending()` и корректная отмена незавершённых операций при уничтожении страницы.

## 4. 🔐 Авторизация и Deep Links
Настроена безопасная навигация через `GoRouter`:
* Редирект неавторизованных пользователей на экран входа с сохранением исходного маршрута.
* Защита от внешних URL в параметре `redirect` и предотвращение *redirect loops*.
* Корректная обработка `onboarding` и обновление состояния роутера через отдельный `notifier`.

## 5. 💉 Dependency Injection (GetIt)
Приведена в порядок работа с контейнером зависимостей:
* Удалено использование устаревшего `allowFactoryRetrieval`.
* Исправлена логика `unregisterAll()`.
* Унифицирована регистрация моков и зависимостей для тестов.
* Исключено ручное создание сервисов внутри виджетов.

## 6. 🧪 Тестирование
Добавлены Unit и Widget тесты для критических сценариев:
* **Address:** Форматирование, копирование, состояния UI, корректный `dispose`.
* **Sync Service:** Успешные запросы, retry после `429`, лимит попыток, игнор `401/500`, идемпотентность, отмена запросов, ошибки локального сохранения.
* **Card Issuing:** Резолв через DI, закрытие BLoC, защита от двойной отмены.

## 7. 🧹 Качество кода
Пройден статический анализатор Dart (`flutter analyze`):
* Удалены `print()` из production-кода.
* Исправлены некорректные `await` для синхронных методов.
* Обновлены конструкторы BLoC под актуальную версию `flutter_bloc`.
* Улучшено управление ресурсами и жизненным циклом объектов.

## 🏗 Архитектура

Проект следует строгой слоистой архитектуре с разделением ответственности:

```text
[ UI (Widgets) ] 
       ↓ (Events)
[ BLoC (State Management) ] 
       ↓ (Calls)
[ Services / Repositories (Business Logic) ] 
       ↓ (Uses)
[ API (Dio) / Local Storage (Data Layer) ]
```
> **Принцип:** UI не знает о существовании сети или базы данных. Бизнес-логика изолирована и полностью покрывается Unit-тестами.
